# 能力边界：本 skill 覆盖到什么程度

> 这份文件存在的理由：一套方法最容易出错的地方，是**高估自己**。
> 下面按「精确算法 / 元启发式 / 最优性证明」三块逐项标出支持度，写清哪些能完整交付、哪些只能给检查表、哪些帮不上。
> **新增能力时必须同步改本表**，否则本表就变成营销材料。

---

## 1. 一句话定位

**这是「设计层 + 评审层」，不是「实现层」。**

- 它能：定路线、挑范式、把模型写对、把解验证住、把对比口径钉死、拦住典型错误。
- 它不能：替你写出高性能代码、替你证明定理、替你判断「这个解在业务上真的合理」。
- 2026-11 起补了四个可运行引擎（ALNS / SA / TS / GA）与自测脚本，**实现层的空白被填了一部分**，但不是全部（见 §4）。

---

## 2. 入口能力：四种起点的支持度

主目标是**从任意一种起点走到一个可优化的场景**，不是只服务「已经有模型」的人。

| 入口 | 支持度 | 依据 / 落点 |
|---|---|---|
| 场景 + 数据 | **完整** | `算例与基准.md` §0.1 七项审计；审计不过关会明确拦住，不放行到建模 |
| 场景，无数据 | **完整（取数）/ 部分（补采）** | §0.0 决策变量 → 字段反查表；§0.2 五级检索。能替你找公开数据、设计合成方案；不能替你去企业内部补采 |
| 数据，无场景 | **完整（构思）/ 部分（判定）** | `场景构思.md`：画像六问、三条构思通道、候选场景卡。能给 3 个目标不同的候选并标 A/B/C；不能替你判断「业务上愿不愿改流程」 |
| 只有一句 idea | **完整（场景化）/ 部分（验证）** | `场景构思.md` §6 四问：谁 / 何时 / 决定什么 / 怎么算好。能逼出可建模的一句话；这个 idea 值不值得做，仍由用户判断 |

> **一句限制**：它能判断「这份数据能不能支撑这个目标」，不能判断「这个目标值不值得追」。

## 3. 精确算法：覆盖最好

| 环节 | 支持度 | 依据 / 落点 |
|---|---|---|
| 选型（该不该上精确、上哪种） | **完整** | `算法手册.md` §1 决策树：按「要不要证书 × 规模 × 有无结构」分流，含全幺模与可分解两条补充判据 |
| MILP 建模与线性化 | **完整** | `模型库.md` + `建模规范.md` §7 八类建模错误；`milp_lab.py` 可直接跑 |
| 下界（LP / 组合 / Lagrangian / 列生成） | **完整** | `松弛与下界.md`：四类都有公式、伪代码、失效条件 |
| 求解器诊断与降级 | **完整** | `运筹内核.md` §5：OPTIMAL / LIMIT / 无许可 / 数值不稳四种情形 |
| 求解效率调优 | **完整**（2026-11 新增） | `求解器调优.md` 四层法 + `solver_bench.py` 参数档案对比 |
| 模型正确性 | **完整** | `建模规范.md` §6 四层检验 + 独立校验器 |
| 动态规划 | **部分** | 仅「状态无后效性 / 复杂度 = 状态 × 转移」与五条技巧，无状态压缩细节 |
| CP-SAT | **部分** | 六行建模对照（区间变量 / NoOverlap / 累计 / OnlyEnforceIf），无完整规范；依赖 OR-Tools，骨架不含 |
| 分支定价 / 分支割 | **设计层** | `算法手册.md` §2.4：结构图 + 四个设计点（定价子问题/列池/分支规则/对偶平滑）+ 失败模式。**无实现**，且本应逐问题定制 |

## 4. 元启发式：设计强，实现有骨架但不全能

| 环节 | 支持度 | 依据 / 落点 |
|---|---|---|
| 范式选型 | **完整** | `算法手册.md` §1.1 八类问题族 → 范式映射；§5.1「不要一上来就 ALNS」 |
| 局部搜索算子 | **完整** | §4 六算子表，含单次复杂度与增量技巧 |
| ALNS 设计与实现 | **完整** | `算法手册.md` §5.3 + `scripts/algotemplates/alns.py`（可运行） |
| 模拟退火 | **完整** | §5.2：初温按接受率 80% 标定、$\alpha$ 由预算反推、链长、重热 + `sa.py` |
| 禁忌搜索 | **完整** | §5.5：禁忌表结构、候选集、特赦、多样化 + `ts.py` |
| **遗传算法** | **完整** | §5.4 七要素表 + `scripts/algotemplates/ga.py`（OX/PMX、swap/insert/reverse、锦标赛、精英、移民、停滞重启、可选 memetic）。注意：纯 GA 在 TSP 上弱于 ALNS/TS 属方法特性，别拿它当主力 |
| 调参纪律 | **完整** | §6：调参集/测试集分离、预算固定、少参数优先 |
| 实现自测 | **完整** | `algotemplates/selftest.py` 三项 + 负对照 |

已验证的事实（不是声明）：四个引擎在 40 点 TSP 上相对构造基线 +17.3%（GA）~ +19.9%（ALNS），各 0.1–1.5 s；ALNS 接到 mFSTSP 上 0.21 s 达到官方 IP 最优 1048.716531（同模型 MILP 需 10.6 s）。

## 5. 最优性证明：最容易被高估的一块

「证明」是四种完全不同的工作，支持度差得很远：

| 证明类型 | 支持度 | 说明 |
|---|---|---|
| 某次求解得到的是最优解（证书） | **完整** | 下界 = 上界这条路径通；`运筹内核.md` §6 措辞纪律（Status=OPTIMAL + MIPGap=0 + 合法下界） |
| 模型与问题等价 | **完整** | 四层检验，含「故意构造违约解确认被拒」 |
| 算法正确性（不变量 / 终止性 / 可行性保持） | **模板级** | `证明规程.md` §2 交换论证、§3 归纳不变量，各带完整范例与自检清单 |
| 近似比 / locality gap | **模板级** | §5 三步法 + §6 最坏实例构造；给的是**套路**，不是结论 |
| 问题复杂度（NP-hard） | **部分** | 要求「给归约来源或引用」；`证明规程.md` §4 给归约模板，但**不替你想归约** |
| 验证你写的证明对不对 | **做不到** | 只能做逻辑质疑（找没证的引理、缺失条件、量词错误），**没有形式化检查**，给不了「这证明成立」的保证 |

## 6. 仍然存在的三项硬限制

1. **分支定价只有设计要点**，没有实现。
2. **证明无法被机器验证**：本 skill 的所有证明产出都是「待人工审阅的草稿」。
3. **CP-SAT / OR-Tools 不在依赖内**：相关建议无法在会话里跑通验证。

另有一条容易误读的事实，不是缺陷但要先说清：

- **GA 有引擎，但通常不该是首选**。40 点 TSP 上 memetic GA 607.4，ALNS 590.8；差距来自「解空间连续性」而非调参。选型顺序见 `算法手册.md` §1.1（构造+局部搜索 → ALNS/TS → GA+LS）。

另外两处结构性偏斜，用的时候要自己校正：

- `算法手册.md` 的重心偏「路径与调度 + ALNS」。若问题是排产（CP-SAT 更合适）、网络设计（Benders）、大规模指派（列生成），指导会偏薄。
- `无人机配送专题.md` 是目前唯一的领域专题；其他领域（生产排程、库存、选址）只有通用条目，没有领域级坑表。

## 7. 什么时候该承认「这块帮不上」

遇到下面这些，直接说清能力边界，比硬给一个像样的产物更有用：

| 诉求 | 本 skill 能给 | 该建议用户去找 |
|---|---|---|
| 「帮我把这个 ALNS 调到 SOTA」 | 结构评审 + 自测 + 调参纪律 | 领域论文的算子细节、开源实现 |
| 「证明我的算法是 2-近似」 | 模板、反例检查、措辞 | 人工推导或形式化工具（Coq/Lean） |
| 「帮我把这个 CP-SAT 模型写出来」 | 建模要点、约束对照表 | OR-Tools 官方文档与示例 |
| 「我的 Gurobi 解出来和业务不符」 | 校验器 + 三问追溯 | 业务方确认规则本身 |

## 8. 维护约定

- 新增任何能力（新引擎、新模板、新领域专题），**必须同时更新本表的支持度与 `SKILL.md` 资源索引**。
- 「完整」的定义：有规程 + 有可运行代码或可核验工件 + 在本仓库真实跑过一次。
- 只写了规程没跑过的，标「设计层」；只跑过一次没沉淀的，不算能力。
