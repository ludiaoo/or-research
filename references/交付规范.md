# 交付规范 · 从结果到可提交的产物

> 实验跑完不等于交付。本文件规定「什么必须写、写在哪、怎么验收」。
> 研究目录由 `scripts/study.py init` 生成：

```
<study_name>/
├── state.json                  # 阶段门进度、决策与思路留痕（不存结论数字）
├── 00_问题界定.md … 07_交付与结论.md
├── 复现清单.md
├── data/                       # 算例与生成参数
├── results/                    # 原始结果，只读
└── figures/                    # 图
```

## 1. `07_交付与结论.md` 七段

**业务方案形态（默认）**

1. **结论清单**：字段 `# | 结论 | 关键数字 | 强度 | 适用条件 | 来源`，每条必须标强度。
2. **执行清单**：`动作 | 责任人 | 时间 | 依赖 | 完成信号`，业务方拿它能直接排期。
3. **方案对照**：现状 vs 优化，按客户/时段/资源维度拆，每个变化带分母与口径。
4. **稳健性与适用条件**：关键参数区间、翻转点、业务方需监控的指标。
5. **局限与未测**：≥3 条，含口径偏离与简化；**刻意保留，不删**。
6. **复现包**：环境、数据版本、命令、预期输出、运行时长。
7. **论文附录（可选，业务方案可删）**：文档结构、图表与正文一致性、审稿人问题 ≥5 条。

**强度分级**（写进每条结论）：

| 级别 | 含义 | 典型措辞 |
|---|---|---|
| 确定（证明） | 有定理与证明 | 「在假设 A1–A3 下，算法 1 得到最优解」 |
| 确定（证书） | 求解器证书 + 独立验证 | 「该算例上求得最优（MIPGap=0，LB=…）」 |
| 有条件 | 在某参数区间成立，或统计显著但依赖样本口径，或只在某种清洗口径下成立 | 「单位成本 ±20% 内方案不变」「n=20，中位 gap 降 1.8 点，p=0.007」「按基线清洗口径成立，激进截尾后翻转」 |
| 仅本算例 | 单场景或少量算例 | 「在 3 个算例上观察到…，未做统计检验」 |
| 未验证 | 文献定位或推测 | 「文献报告…，本次未复现」 |

> **数据依赖也要进分级**：若结论在「保守 / 基线 / 激进」三档清洗下不一致，或换掉某个 `[假设]` 参数就变，必须写「有条件（依赖清洗口径 / 依赖假设值）」，并点名是哪个动作、哪个参数导致的。只写「有条件」不写依赖项，等于没降级。

## 4. 措辞纪律

- 负结果、被推翻的结论、不显著的 p 一律照写；「局限 / 还没测」不删。
- 不声称未测过的事：更大规模、联合扰动、与外部算法对比。
- 区分「统计证据」与「最优性证据」；最优性结论必须带口径。
- 只报相对量；绝对目标值不跨文献比较。
- 措辞带样本规模：「20 算例 × 5 种子，同种子配对」，不写「实验表明」。
- `p > 0.05` 写「不显著 / 分不出高低」。
- 区分「参考模型 / 公开报告值」与「本研究实现」。
- 写「按使用者确定的口径」前，确认该项确实来自用户回答。

---

## 5. 图表规范

- 图内语言统一；图例挂坐标区外，不遮数据。
- 敏感性每点多个独立种子取均值 + 误差棒。
- 中文回退字体不要用带点阵字模的字体；`font.family` 给列表。
- 图与表逐格一致，同一算例来自同一次求解。
- 表格统一小数位：gap 两位、时间一位。
