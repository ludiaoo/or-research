# 通用踩坑清单

> 按「什么时候会撞上」组织。每条都是一类真实事故，剥掉项目名，只留机制。
> **写代码前扫一遍；结果反常时回来查一遍。**

## A. 跑实验 / 落盘

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| A1 | 用会话默认解释器跑项目代码 | 可能没装 numpy/scipy，导入即崩 | 先验证：`python -c "import numpy, scipy"`；用项目 venv 显式路径 |
| A2 | 实验臂输出名沿用默认值 | 直接覆盖基线结果 | 每臂独立名；基线文件标只读 |
| A3 | **续跑去重键不含实验配置** | 同名结果已有 `(算例, 种子)` 就被判「已完成」，换开关再跑**整批静默跳过** | 去重键包含全部会改变结果的配置；或每臂换文件名 |
| A4 | 以 `w` 打开结果文件 | 清空已有证据 | 只对确定重跑的非基线臂使用，先备份 |
| A5 | 手改 `results/*.csv` 数字 | 证据链断裂 | 数字不对就重跑 |
| A6 | 快速验证（小轮数/少种子）的数字 | 只验链路，不具统计意义 | 独立文件，绝不进报告 |
| A7 | 单任务失败拖垮整批 | 重跑代价高 | 逐行落盘、可续跑；失败按命令单独重跑 |

## B. 口径与统计

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| B1 | 不同样本口径混用 | 同一张表混了全量与子集，结论不可比 | 见 `实验与统计.md` §2；`paired_stats.py --expect-n` 强制核对 |
| B2 | 子集假象 | 小样本显著、全量不显著甚至反号 | 新结论用全量；子集只做边界复核 |
| B3 | 把「各种子取最优」当配对 | 两个最小值都带极值偏差 | 优先配对口径；取最优口径单独标注 |
| B4 | 单种子画敏感性曲线 | 种子噪声大于效应时曲线反向 | 每点多独立种子取均值 + 误差棒 |
| B5 | 并列混进符号检验 | 稀释均值、虚高 p | 含并列均值 + 去并列检验，两者都报 |
| B6 | 单参数敏感性外推到联合扰动 | 叠加数值不可由单参数推得 | 只报单参数区间；联合扰动列为局限 |
| B7 | 复算的 p 与历史文档不符就改数字 | 抹掉线索 | 先查方法与配对集，不要改已有数字 |
| B8 | 内连接静默丢配对 | n 悄悄变小 | 每次报 A/B 独有行数并核对 n |
| B9 | 效应小就判定算法有缺陷 | 可能只是该成本项占比极低 | 先算成本结构，必要时给算术上界 |

## C. 解的表示与校验器

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| C1 | 用数组下标引用对象 | 增删节点后下标平移，关联挂错 | 一律用稳定编号 |
| C2 | 回写解时静默丢对象 | 少服务却更便宜，甚至**比最优还低** | 完整性校验必须保留；成本异常低先查结构 |
| C3 | 漏检「同一资源同时占用」 | 求解器专找这种非法解，成本低估十几点 | 违约码覆盖全部耦合约束 |
| C4 | 早退路径丢违约标签 | 诊断结果缺一半 | 早退只筛候选，诊断走完整版 |
| C5 | 时间窗写成 $T_j\le l_j$ | 少递推，约束形同虚设 | 逐条对照模型卡编号 |
| C6 | 绝对时刻与相对时窗混用 | 时间维度失效 | 统一以班次起点为 0 |
| C7 | 收紧可行域后目标反而变好 | 搜索未收敛或约束方向反了 | 定义一致性不变量，违反就重跑 |

## D. 模型与结论解释

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| D1 | 把「禁止某动作」理解成「放开约束」 | 逻辑反向，判据失效 | 用集合包含关系复核：收紧后可行域应变小 |
| D2 | 忽略「免费/无限/零耗时」的隐含假设 | 换成计费口径后结论可能翻转 | 涉及等待、切换、库存的结论双口径复核 |
| D3 | 把 0.00% 读成「收益衰减」 | 实则结构上无从发生 | 先查机制再解释数字 |
| D4 | 精确模型的结论外推到带额外约束的场景 | 精确模型常省略现实约束 | 最优性结论必须写口径限定 |
| D5 | 自定系数的绝对成本与文献直接对照 | 口径不同不可比 | 只报相对量 |
| D6 | 把「参考模型」与「本研究实现」混为一谈 | 归属错误 | 明确区分出处 |

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| E1 | 回归基线不一致就刷新基线 | 把语义变更伪装成优化 | 先查语义；有意变更要记录并全量重跑 |

## F. 交互与决策留痕

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| F1 | 把 AI 默认值写成「用户决定」 | 适用条件失真 | 标 `[AI 建议]`，gate 单独确认 |
| F2 | 「都行」「你看着办」当确认 | 决策没采集 | 给 2–3 个具体选项及后果 |
| F3 | 只写「已确认」，不记理由来源 | 无法追溯 | 决策 + 理由 + 来源 + 时间都留痕 |
| F4 | 改主意后沿用旧决策与旧结果 | 结论基于已推翻口径 | `reopen` 清空后续并重跑 |
| F5 | 先写完产出再问「行吗」 | 用户只能点头 | 开场先 `ask`，回答作为输入 |

## G. 建模与求解器

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| G1 | 用聚合约束（$\sum_j x_{ij}\le n y_i$）当强形式 | LP 界退化到平凡界，节点爆炸 | 用逐条 $x_{ij}\le y_i$；`milp_lab.py compare` 实测 |
| G2 | Big-M 取 $10^9$ | LP 松弛烂、数值不稳 | 取最小合法值，做 M 敏感性 |
| G3 | LP 与 MILP 用了不同约束集 | integrality gap 无意义 | 同一矩阵，只切 `integrality` |
| G4 | 忽略对称解 | 分支树爆炸、时间方差大 | 破缺约束（$y_k\ge y_{k+1}$ 等） |
| G5 | 把启发式最好解当下界 | gap 虚低、写「最优」站不住 | 下界只来自松弛/对偶/组合界 |
| G6 | 只看 `ObjVal` 不看 `ObjBound`/`Status` | 超时也写「最优」 | 六字段齐全；`LIMIT` 只能写「时限内最好」 |
| G7 | 小算例不与枚举/DP 对照 | 模型写错却「求解成功」 | 小规模独立精确解逐位对照 |
| G8 | 不同 formulation 的整数解不一致 | 模型不等价 | 交叉验证目标值；不一致就查约束 |
| G9 | 把 integrality gap 当算法 gap | 概念混淆 | 分开定义、分表报告 |
| G10 | 换求解器后字段含义不同 | 报告口径混乱 | HiGHS `mip_dual_bound` vs Gurobi `ObjBound`，注明来源 |

## H. 结果解释与写作

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| H1 | 结果比下界还低 | 解不可行或目标算错 | 独立校验器重算；查参考值口径 |
| H2 | 单算例观察写成普遍结论 | 审稿人一击即中 | 标「单例观察」，补统计或降级 |
| H3 | 绝对目标值跨文献比较 | 坐标系/常数不同，数字无意义 | 只比 gap，注明参考值类型 |
| H4 | 把 BKS 当 OPT | 声称「达到最优」 | 标类型；除非原文证明 |
| H5 | 在测试算例上调参 | 数据泄漏 | 调参集/测试集分离，预算固定 |
| H6 | 算例挑过、只报赢的 | 结论不可信 | 事前定算例集，全报含失败 |
| H7 | 时间上限/硬件不写 | 无法比较 | 写 CPU、线程、时限；跨论文只比 gap |
| H8 | 局限只写「未来工作」 | 显得回避问题 | 至少 3 条具体未测项 |

## I. 实现与分析陷阱（最容易自己骗自己的一类）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| I1 | 用浮点比较判断「是否达到最优」：`if len(bars) - res.fun == 0` | `16.000000000000004` 之类别差，把「已达最优」判成「差一点」——实测把 98% 达最优误报成 82% | 目标值先 `round()` 成整数再比；比例只用于展示，判定用绝对差 |
| I2 | 灵敏度测试靠改模块常量，而函数签名是 `def f(kerf=KERF)` | 默认参数在**定义时**绑定，改 `module.KERF` 完全不生效，所有档位跑出同一个数 | 默认值写 `None`，函数体内 `kerf = KERF if kerf is None else kerf`；或显式传参 |
| I3 | 以为「校验器通过」= 「方案对」 | 校验器只保证模型内部一致；口径读错（240cm 当 240mm）照样全部通过 | 加第二层：与**业务确认清单**逐项比对（本例查出 9 件不符） |
| I4 | 缺依赖时直接抛 traceback | 用户以为程序坏了，不知道还能降级 | 捕获 ImportError 并给两条明确出路（换解释器 / 去掉该功能） |
| I5 | 数值列里有 `240cm` 这种值 | 既不进分位数、也不进规则检查，**静默消失** | 单独报「无法解析的值 + 样例」；并做量级比对，判断是否单位混用 |
| I6 | 报「省了 13%」，但同表不报少切件数 | 指标改善来自少干活（少切/少服务/少覆盖） | 目标值与「缺口」必须同表；缺口 > 0 的方案不得进汇报 |
| I7 | 把**条件字段**当全量字段：交期只在加急单填（13%），却拿它算「全厂准时率」 | 分母悄悄换成 13% 的行，结论覆盖不了 87% 的业务 | 先看缺失结构：某列缺失若被另一列完全解释，就只在有定义的子集上算并报覆盖率；补值等于编业务规则 |
| I8 | 产能套行业默认值：「一天一班 8 小时」 | 实测 3 台机算出 285% 负荷——机器不可能连续 5 个月超 100% 运转，荒谬数字会被当成「产能爆炸」的结论 | 从时间戳反推：日强度（总工时÷作业日）、作业日覆盖率、相邻工单间隙；负荷率 > 100% 时先怀疑口径 |
| I9 | 基线是**随机派单**或合成数据，却把「可降 21%」当真实收益 | 改善幅度全部来自弱基线，换真实场景可能只有 3% | 基线的强弱决定分母；写明基线怎么来的，并说明「真实排产基线通常更强，幅度会收窄」。**检验法**：拿一条五行规则（LPT / EDD / FFD）跑一遍，若它把观测值甩开一大截，说明观测值不是有经验决策，所有「相对现状」的改善都要降级 |
| I10 | 模型带时间推演（完工日、交期、班次），却只报「优化后 vs 优化前」 | 模型日历偏乐观，偏差全被算成改进。实测：加急单观测逾期 5/51，模型重放现状只 2/51，于是「优化把逾期降到 2/51」成了假改善 | 必须**三口径同表**：① 观测真值（现实）② 模型重放现状（同一套日历，作桥）③ 模型优化（与② 比才有意义）。②与③ 的差才是优化的贡献，②与① 的差是模型的偏差 |
| I11 | 口径改了（目标单位、产能定义、清洗策略），旧脚本和旧数字还留在目录里 | 同一项目出现两个互相矛盾的结论，后来者引用了作废的那个。实测：旧脚本按原始工时报「降 21.2%」，新口径只有 5.4% 且方案物理上做不完 | 口径变更时，旧脚本要么删、要么在文件头写明「已作废，仅作反面对照」，新口径文档里显式写「旧数字 X 作废，原因 Y」；`verify.py` 加一条数字抽查，把旧数字钉死为不一致 |
| I12 | **规程只写在 reference 里，模板里没有落笔位置，过门校验里没有拦截** | 这条规程等于不存在。实测：`场景构思.md` §6 有四问、`00` 模板的入口表也写着「只有 idea → 场景化四问」，但 `00` 的章节里没有四问的表，`pass 0` 只校验「数据无场景」一个入口——四条入口里有三条的第一产出无处落笔、无人检查 | 每条规程都要在**三个地方**同时存在：① reference 写清怎么做 ② 模板给出可填的空表 ③ 过门校验按入口分派拦截。缺任一条，就只能是「看的时候觉得对，做的时候全忘了」。**检验法**：把每个入口各走一遍，看它的「第一步产出」能不能在模板里找到同名小节——找不到就是缺陷 |
| I13 | **判据措辞放宽到「生成器 + 种子」，全合成的研究就能合规走完全部 8 道门** | Stage 3 原来只要求「算例来源可复现（库版本**或**生成器 + 全部种子 + 参数）」，合成算例天然满足。实测：E4 入口下一张真实数据都没有，Stage 3 静默放行，后面每个「降 27.8%」都可以合规地写进 Stage 7，而唯一拦住它的是 `00` §0.6 的一句文字纪律 | 凡「允许降级」的判据，都要配套一个**显式认下**的动作：`pass 3 --accept-synthetic` 留痕 + 三条限制落到状态里（`status` 会持续显示「算例=合成」）；Stage 7 再查一次交付文档有没有免责字样。判据里的「或」是最容易漏的地方——它把例外写成了并列项 |

**同类：入口分诊对四个入口说同一套话。** `ask` 一次性抛出 15 个决策点，对只有 idea 的用户先问
「数据有没有官方参考值」「清洗口径」——而 skill 自己写着「按决策变量反查数据需求，再取数」，顺序是反的。
用户此时只能答「不知道」，问答一轮就空转。正确做法是在 `ask` 输出里按 E1 分派提示，并明确
「入口未定时 D1–D6 允许先答『待定 + 为什么现在答不了』，场景冻结后回填不算跳门」。
