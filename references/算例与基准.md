# 算例与基准 · 让结果可比

> 审稿人不会因为你「在自己的随机算例上提升 12%」而信服；他们会问：**这些算例代表什么、和谁比、参考值从哪来**。

---

## 0. 数据契约（Stage 0 就要定，不是 Stage 3 才想）

先回答四个问题，答案写进 `00_问题界定.md` §0，再谈建模。

| 决策 | 可选答案 | 选错的后果 |
|---|---|---|
| 从哪来 | 使用者提供 / 公开基准 / AI 合成 / 混合 | 到 Stage 3 才发现没数据，前三阶段白做 |
| 有无参考值 | OPT / BKS / LB / 都没有 | 没有参考值却写「提升 x%」，分母是自造的 |
| 允许怎么处理 | 原样 / 清洗裁剪 / 重采样补齐 | 处理不可追溯，结果无法复现 |
| 结论边界 | 可外推 / 仅本算例族 / 仅算法相对表现 | 合成数据写成实际效益，等于编数据 |

### 0.0 从场景反查数据需求（有场景、没数据时先做这一步）

不要一上来就问「有没有公开算例」。先把**决策变量拆开**，变量里出现什么，就必须有什么数据——这张表决定了你到底缺什么、能不能用替代量。

| 决策变量 | 必需数据 | 缺了会怎样 |
|---|---|---|
| 派谁去哪条线 | 资源清单与容量、任务点需求、点间时间/距离 | 只能做静态分配，不是路径问题 |
| 什么时刻开始/结束 | 时间窗、服务时长、班次规则 | 时间维度整体丢失，退化成纯空间问题 |
| 派几台设备/几架无人机 | 资源数量、单次任务时长上限（续航、换电、班次长度） | 无法判定可行性边界，模型会给出不可执行的解 |
| 各产品做多少 | 产能上限、单位工时、最小批量 | 只能做配比，做不了产能约束 |
| 补多少库存 | 期初库存、补货提前期、需求分布 | 算不出缺货成本，目标只能改成服务水平 |
| 走哪条路/在哪个点换乘 | 路网拓扑、通行限制、换乘代价 | 只能用直线距离代理，结论强度降一档 |

**三步做完才算摸清**：

1. 把候选模型的决策变量逐条列出（哪怕只是草稿）。
2. 每个变量对应到「哪个文件、哪一列、什么单位」；找不到就写「无」。
3. 对「无」的项标注处理方式：**补采 / 公开基准 / 合成 / 代理量**。用代理量必须写清代理关系与偏差方向（例：用直线距离代理路网时间，系统性低估，城市路网通常低估 20–40%）。

> 允许「先建模、后找数」，但模型里所有缺数据的参数必须标 `[假设]`，并在 Stage 6 对最敏感的 2–3 个做敏感性扫描——否则结论只是假设的回声。

### 0.1 使用者提供的数据

必须做审计，产出一份数据质量报告（`data/audit.md` 或 JSON 均可）：

| 审计项 | 检查什么 | 常见问题 |
|---|---|---|
| 覆盖完整 | 点到点距离/时间矩阵是否有缺项 | 只给上三角、缺 depot 回程弧 |
| 对称性 | $t_{ij}$ vs $t_{ji}$ | 路网有单行道 → 不对称是正常的，但必须记录 |
| 三角不等式 | $t_{ij} \le t_{ik}+t_{kj}$ | 违反说明有捷径或坐标错位 |
| 自环 | $t_{ii}=0$ | 非零说明索引错位 |
| 量纲与范围 | 秒/分、米/英里、经纬度 vs 投影坐标 | 单位混用是最常见的静默错误 |
| 坐标一致性 | 节点是否落在地图 bbox 内 | 个别点飞到海里 |
| 孤立点/不可达 | 是否存在无法被任何路径服务的点 | 会让模型直接不可行 |

纪律：**原始文件只读**，所有清洗写成脚本，保留处理前后对照与校验和。

### 0.2 公开基准（AI 去检索）

- 先确认这个领域有没有事实标准（见 §1）；有就别自造。
- 锁定：库名 + 版本 + 下载日期 + 文件校验和（`sha256`）。
- 官方参考值随数据一并落地，标 `OPT/BKS/LB` 并注明来源文献；**不同版本的 BKS 不得混用**。
- 只给算例不给参考值的情况很常见（只有解文件、没有目标值）：那就自己算，并写明「参考值为本次求解所得，非官方」。

**检索顺序**（按可靠性从高到低）：

| 顺序 | 去哪找 | 要拿到什么 |
|---|---|---|
| 1 | 论文正文 / 附录 / 在线补充材料（supplementary） | 算例生成规则、参数表、结果表 |
| 2 | 作者 GitHub / 个人主页 / 实验室页面 | 原始数据文件、求解代码、解文件 |
| 3 | 数据仓库：Zenodo、Mendeley Data、Figshare、Dryad、HARVARD Dataverse | 带 DOI 的可引用版本 + 校验和 |
| 4 | 领域标准库（OR-Library、CVRPLIB、TSPLIB、MIPLIB 等，见 §1） | 算例文件 + 官方参考值 |
| 5 | 开放数据门户（政府交通/物流开放数据、Kaggle、UCI） | 原始记录；需自己构造算例，不能直接当 benchmark |

**只有 PDF 表格时**：允许转录，但必须（a）说明是转录而非原始文件，（b）两人或两次独立转录后 diff，（c）抽样与原文数字逐位核对。转录误差是最隐蔽的复现失败原因。

### 0.3 AI 合成

生成器必须写清五件事：分布、参数、规模、种子、与真实数据的偏差。

- 种子全记录；主实验用多组种子（≥5），不许只报最好那组。
- 合成算例只能支撑**算法相对表现**（谁比谁好、gap 多大），不能支撑「实际节省 x% / 成本下降 y 元」。
- 若用真实数据的边缘分布做校准，说明校准了哪些维度、没校准哪些。

### 0.4 降级顺序

用户有数据 → 审计即用；否则锁一个公开基准；再否则合成并全程标注；规模档仍不足就收窄研究边界，不许假装覆盖。

## 1. 标准算例库

| 领域 | 库 / 来源 | 典型算例 | 备注 |
|---|---|---|---|
| 选址 p-median / UFL | OR-Library（Beasley 维护） | `pmed1`–`pmed40`（$n=100\sim900$） | 文件含最优值或最好已知值，**用前核对版本** |
| 车辆路径 | CVRPLIB（Uchoa 等 2017 的 X 集；Christofides 等经典集） | $n=100\sim1000$ | X 集有统一生成规则，适合比算法 |
| VRPTW | Solomon (1987)；Gehring–Homberger | 25/50/100；200–1000 | 客户分布分 C/R/RC 三类，别只报一类 |
| TSP | TSPLIB（Reinelt 1991） | `berlin52`、`eil101`、`pr1002` | 有最优值，适合验证 |
| 装箱 / 切割 | BPPLIB | 多类规模 | 有下界，便于算 gap |
| 通用 MILP | MIPLIB 2017 | 分 benchmark / collection | 只适合「通用求解器性能」，不适合领域结论 |
| 作业车间 | Taillard；Brandimarte（柔性） | 15×15 起 | 有最好已知值 |
| 背包 | Pisinger 算例 | 强相关 / 弱相关 / 子集和 | 分布极影响难度 |
| 卡车—无人机 | 原始论文附录 / 作者主页（Murray & Chu 2015；Murray & Raj 2020） | 小规模为主 | 自制扩展要说明与原文的差异 |

**使用纪律**：

- 记录**库名、版本/下载日期、文件清单**；不同版本的 BKS 会变。
- 参考值类型必须标：`OPT`（已证最优）/ `BKS`（最好已知）/ `LB`（下界）。三者不可混用。
- 标准库的坐标/取整方式会影响目标值；不要自己「顺手」四舍五入。

## 2. 自制算例：生成器规范

若没有合适标准库，生成器必须可复现：

```python
def generate(seed, n, m, dist="uniform", **kw):
    """返回 instance dict；生成规则写进 README。"""
```

必须写清：

| 项 | 必须记录 |
|---|---|
| 分布 | 均匀 / 聚类 / 真实数据抽样；聚类要给簇数与半径 |
| 参数 | 规模、容量、时间窗宽度、速度、续航 |
| 种子 | 全部列出（不是只写「随机种子」） |
| 与真实的差异 | 例如「真实订单有早晚高峰，本生成器没有」 |
| 版本 | 生成器改动 = 换样本，历史结果不可直接比较 |

规模分档建议：

| 档 | 用途 | 要求 |
|---|---|---|
| S | 正确性验证 | 能与枚举/DP 对照，规模小到可证最优 |
| M | 调参 | 代表性够，跑一次不超过调参预算 |
| L | 主实验 | 覆盖目标规模，5–10 个算例/档 |
| XL | 压力测试 | 只报可行性与时间，不参与均值 |

## 3. 基线怎么选

至少三条中的两条：

1. **求解器直接解**（MILP/CP-SAT，给时限）——回答「为什么不直接用求解器」。
2. **经典构造式**（贪婪/节约/最近邻）——回答「比朴素方法好多少」。
3. **文献方法复现**（若可行）——回答「比 SOTA 如何」；复现要写清参数与适配改动。

基线必须**同样调参、同样时限、同样硬件**。基线弱 = 提升虚高，这是最常见的拒稿理由之一。

## 4. 参考值与 gap

| 参考值 | 含义 | 用法 |
|---|---|---|
| `OPT` | 已证明最优 | 可直接算 gap，最强 |
| `BKS` | 文献最好已知 | 算 gap，但要注明「截至某年」 |
| `LB` | 合法下界 | 算 gap 是上界估计；结果可能负（说明 LB 弱或解更好） |

$$
\text{gap\%} = \frac{z - z_{\text{ref}}}{|z_{\text{ref}}|}\times 100
$$

- 最小化问题，gap 为负说明**你的解比参考值还好** → 先查可行性，再查参考值是否过期。
- 平均值与中位数都报；分布偏斜时中位数更可靠。
- 超时/失败必须单列，不能当 0 或当最大值混进均值。

## 5. 硬件与时间口径

论文里必须写：

- CPU 型号、主频、内存、**单线程还是多线程**；
- 各档时间上限（秒），是否含建模/读数据时间；
- 是否多次运行取最好（若是，写次数与分布）；
- 与文献对比时：**只比 gap，不比绝对时间**（机器不同）。

绝对目标值不可跨论文比较——坐标系、距离度量、常数项都可能不同。

## 6. 常见坑

| 坑 | 后果 | 处理 |
|---|---|---|
| 算例版本不一致 | 数字对不上 | 记录下载日期与文件哈希 |
| 把 BKS 当 OPT | 声称「达到最优」 | 标类型；除非原文证明 |
| 只用一个分布 | 结论不可外推 | 至少两类分布，写进局限 |
| 自制算例太简单 | 算法差异被淹没 | 加对抗性算例（紧约束、退化） |
| 时间上限比基线松 | 不公平 | 统一时限，或做时间-质量曲线 |
| 算例挑过 | 结论不可信 | 事前定算例集，全报 |
