# 算法实现模板 · 接入契约与自测

> 骨架在 `scripts/algotemplates/`，纯标准库，无第三方依赖。
> 它保证的是**工程正确性**（增量算得对、种子可复现、算子不会静默失效），
> 不保证算法设计好——设计仍按 `算法手册.md` §1–§5 自己判断。

---

## 0. 什么时候用，什么时候别用

| 情形 | 用骨架 | 说明 |
|---|---|---|
| 要写 ALNS / SA / TS / GA 的骨架部分 | 是 | 选算子、接受、记账、留痕，这些与问题无关 |
| 要验证增量评价写对了没 | 是 | `selftest.py` 直接可用 |
| 问题能抽象出「解 + 移动」 | 是 | 绝大多数组合优化都满足 |
| 需要列生成 / 分支定价 | 否 | 骨架不覆盖，见 `算法手册.md` §2.4 |
| 需要 CP-SAT 建模 | 否 | 用 OR-Tools，见 §2.2 |
| 只是想跑个求解器拿最优 | 否 | 直接用 MILP，不要为了「有算法」而上启发式 |

## 2. Problem 接口契约

只实现你需要的那一组。引擎在缺方法时会直接报错，不会静默跳过。

| 方法 | ALNS | SA | TS | 契约 |
|---|---|---|---|---|
| `initial(rng)` | 必需 | 必需 | 必需 | 返回**可行**解；不可行就在 SA/TS 里抛异常（不做罚函数兜底） |
| `evaluate(sol)` | 必需 | 必需 | 必需 | 越小越好；必须与你的独立校验器口径一致 |
| `is_feasible(sol)` | 可选 | 可选 | 可选 | 默认 True；**强烈建议**接独立校验器，别复用构造逻辑 |
| `copy(sol)` | 可选 | 可选 | 可选 | 默认 `deepcopy`；解很大时自己实现浅拷贝 + 只读约定 |
| `destroy_ops()` | 必需 | - | - | `[(名字, fn(sol, rng) -> sol)]`，返回**部分解** |
| `repair_ops()` | 必需 | - | - | `[(名字, fn(partial, rng) -> sol)]`，负责补全并保证可行 |
| `neighbor(sol, rng)` | - | 必需 | - | 返回 `(新解, 移动)`；移动用于禁忌/留痕 |
| `moves(sol)` | - | - | 必需 | 可迭代的候选移动；规模大时内部抽样 |
| `apply(sol, move)` | - | - | 必需 | 返回**新对象**，不改入参 |
| `delta(sol, move)` | - | 可选 | 可选 | 默认全量重算（正确但慢）；性能敏感必须重写 |
| `move_key(move)` | - | - | 必需 | 禁忌键，**必须规范化**（如保证 $i<j$） |

两条硬约定：

1. **随机性只能来自传入的 `rng`**。用全局 `random` / `np.random` 会让种子失效，可复现性测试会失败。
2. **`apply` / `neighbor` 不改入参**。ALNS 已经传入 `copy`，但 SA/TS 直接传当前解，就地修改会破坏轨迹。

## 3. 接入四步

### 第一步：继承 Problem，写三个最小方法

```python
from base import Problem

class MyProblem(Problem):
    name = "my-problem"

    def initial(self, rng):
        return construct_greedy(self.data)      # 必须是可行解

    def evaluate(self, sol):
        return objective(self.data, sol)        # 与校验器同口径

    def is_feasible(self, sol):
        return my_validator(self.data, sol)     # 复用独立校验器
```

### 第二步：给目标引擎补方法

ALNS 补 `destroy_ops` / `repair_ops`；SA 补 `neighbor`；TS 补 `moves` / `apply` / `move_key` / `delta`。

**破坏-修复必须闭环**：每个破坏算子移出的元素，修复算子要能全部放回且保持可行。做不到就加惩罚项并明确写进目标，不要靠「大部分时候能修回来」。

### 第三步：先跑自测，再跑算法

```python
from selftest import check_delta, check_feasibility, check_determinism

print(check_delta(MyProblem(), n_cases=30).report())
print(check_feasibility(MyProblem(), checker=my_validator, n_cases=20).report())
```

`check_delta` 失败通常有四种原因：

| 现象 | 原因 |
|---|---|
| 全部差一个常数 | `delta` 忘了算闭合边（首尾相接那条） |
| 只有边界移动错（$i=0$ 或 $j=n-1$） | 取模写错 |
| 误差很小但超容差（$10^{-6}$ 级） | 用浮点累加出误差；改用与 `evaluate` 相同的求和顺序 |
| 忽大忽小 | `delta` 与 `apply` 对移动的语义理解不一致（一个把 $j$ 含在区间内，一个不含） |

### 第四步：跑算法，看轨迹而不是只看终点

```python
res = ALNS(MyProblem(), max_iters=5000, seed=42).run()
print(res.summary())
print("首达最终值×1.02:", res.trace.steps_to(res.best_obj * 1.02))
print("面积(高于最终值):", res.trace.area_above_final())
```

`steps_to` 和 `area_above_final` 用来回答「收敛得多快」，比只报终点值信息量大。注意 `area_above_final` 不是严格的 primal integral（后者需要参考值），报告时要写清定义。

## 4. 四个引擎的必调参数

### ALNS

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `max_iters` / `time_limit` | 2000 / None | 二选一；对比实验用 `time_limit` |
| `segment` | 50 | 算子多时调小（如 30），少时调大 |
| `reaction` | 0.1 | 越大越跟手，越小越稳；算子表现差异大时调大 |
| `sigma` | (33, 9, 13) | 经典 Ropke–Pisinger 取值，一般不动 |
| `T0` | 自动标定 | 想复现文献参数时才显式给 |
| `min_weight` | 0.05 | 算子多时调小，否则每个都被强制探索、拉低质量 |

**接线检查**：跑完后看 `meta["final_weight_d"]`。如果某个算子权重停在 `min_weight`，说明它几乎从不产生改进，应该删掉或重写——这就是消融的证据。

### SA

| 参数 | 默认 | 说明 |
|---|---|---|
| `T0` | 自动（初始接受率 80%） | 自动值通常比手调好 |
| `alpha` | 由预算反推 | 给了 `max_iters` 和 `L` 就不用管 |
| `L`（链长） | 100 | 设为邻域规模的同阶量；设成 1 会退化成随机游走 |
| `T_end_ratio` | 1e-3 | 末温/初温；太小则后期纯贪婪 |
| `reheat_after` | None | 连续多少层无改进就重热；开它要多跑预算，否则 anytime 变差 |

### TS

| 参数 | 默认 | 说明 |
|---|---|---|
| `tenure` | 10 | **必须做敏感性**（5/10/15/20），写进实验 |
| `candidate_limit` | 200 | 全邻域太大时抽样；太小会漏好移动 |
| `aspiration` | True | 关掉通常变差，除非你在做对照 |
| `diversify_after` | None | 停滞多少步重启；开了要报告 `restarts` 次数 |
| `recompute` | True | False 用增量累加，快但误差会沿迭代累积 |

### GA

| 参数 | 默认 | 说明 |
|---|---|---|
| `pop_size` | 60 | 太小早熟，太大每代开销翻倍；先按 50–100 试 |
| `max_iters` | 500 | 这里一代 = 整代评价，别与 SA 的「一次移动」混算预算 |
| `crossover` | `"ox"` | 排列用 `ox`/`pmx`；非排列问题请实现 `Problem.crossover` |
| `crossover_rate` | 0.9 | 降到 0.6 会退化成「带变异的随机游走」 |
| `mutation_rate` | 0.2 | 停滞时自动 ×1.5（上限 0.6） |
| `elite` | 2 | 保精英；设 0 会丢最优，设太大早熟 |
| `immigrants` | 2 | 每代替换最差个体的随机新解，防整群同 basin |
| `stagnation_restart` | 80 | 连续多少代无改进就重启（保最优，一半重新构造） |
| `local_search` | 0 | 每个子代抽多少个候选移动做首次改进；开它就是 memetic |

**GA 的三个特有陷阱**（前两个比参数重要得多）：

1. **不可行子代**：非排列编码下，交叉几乎必然破坏可行性。看 `meta["rejects"]`——拒绝率 > 50% 说明编码或交叉算子选错，不是参数没调好。正确做法是实现 `repair` 或换表示，**不要用罚函数把不可行解放进来**。
2. **种群同质化**：看 `meta["uniq"]`（去重后的不同解个数）。若远小于 `pop_size`，交叉已退化为复制，此时调交叉率没用，要加 `immigrants` 或提高变异率。
3. **预算不可比**：GA 的一代包含 `pop_size` 次评价。与 SA/TS 比时要换算成**评价次数**或 wall-clock，直接比 `iters` 会得出反的结论。

**单独 GA 通常打不过 ALNS/TS**（40 点 TSP 实测：GA 612 vs ALNS 591 vs TS 592 vs SA 606，同一预算量级）。这不是实现问题，是方法特性：交叉负责重组、局部搜索负责精修，组合优化里几乎总要配后者。所以选型顺序是「构造 + 局部搜索 → ALNS/TS → GA(+LS)」，GA 的正当用途是**解有天然排列/分组结构、且交叉能保留有用块**的场景。

## 5. 自测三件套

| 函数 | 检查什么 | 失败意味着 |
|---|---|---|
| `check_delta(prob, ...)` | 增量 vs 全量逐移动对撞 | 搜索方向系统性偏移，结果不可信 |
| `check_feasibility(prob, checker, ...)` | `is_feasible` vs 独立校验器 | 会返回「可行」的不可行解 |
| `check_determinism(run_fn)` | 同种子两次运行 | 有全局随机源或时间依赖，复现失败 |

`selftest.py` 自带**负对照**：故意把 `delta` 写成常数，自测必须报 FAIL。如果你的自测连明显错误都抓不到，说明测试本身失效——这比没有测试更危险。

## 6. 七个常见接入错误

| 错误 | 症状 | 修法 |
|---|---|---|
| `apply` 就地修改入参 | 轨迹记录全变成同一个值；TS 禁忌判断错乱 | 返回新 list/dict |
| 用全局 `random` | 换种子结果一样，或换了机器不一样 | 只用传入 `rng` |
| `move_key` 没规范化 | 禁忌表几乎不命中，TS 退化成爬山 | 保证等价移动同键（排序、取模） |
| `delta` 与 `apply` 语义不一致 | 自测偶尔失败、算法「能跑但质量差」 | 用同一个区间定义；重写后必跑自测 |
| 修复算子不保证可行 | ALNS 抛「连续 N 次不可行」 | 修复里做插入可行性检查；或改软约束 |
| `evaluate` 与校验器口径不同 | 结果比下界还低，或官方值对不上 | 目标函数只从校验器取数 |
| 解对象没有可复制语义 | 结果随机漂移 | 用不可变结构，或实现 `copy` |

## 7. 真实接入片段（mFSTSP 一类「路径 + 架次」问题）

```python
class MFSTSP(Problem):
    def __init__(self, inst):
        self.inst = inst

    def initial(self, rng):
        return truck_only_route(self.inst)          # 构造式基线

    def evaluate(self, sol):
        return check(self.inst, sol)["makespan"]    # 直接复用独立校验器

    def is_feasible(self, sol):
        return check(self.inst, sol)["feasible"]

    def destroy_ops(self):
        return [
            ("remove_customer", self._rm_customer),   # 移出一个客户（可能是无人机客户）
            ("remove_sortie", self._rm_sortie),       # 整架次拆掉，客户回卡车
            ("remove_segment", self._rm_segment),     # 连续一段
        ]

    def repair_ops(self):
        return [
            ("best_insert_sortie", self._ins_sortie), # 优先尝试插架次
            ("best_insert_truck", self._ins_truck),   # 退化到卡车插入
        ]
```

要点：`evaluate` 直接调 `check()`，**不要另写一套目标计算**。两套算法迟早会漂移，而漂移之后所有数字都要重跑。
