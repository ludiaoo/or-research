# 运筹内核 · 一份研究必须拿出的硬工件

> 判别标准：**没有公式、没有下界、没有最优性证书的产物，不是运筹优化研究，只是实验报告。**
> 本文件定义八类工件的最低标准；`阶段门判据.md` 与骨架里的描述如与本文冲突，**以本文为准**。

---

## 1. 八类硬工件

| # | 工件 | 必须包含 | 不合格表现 |
|---|---|---|---|
| 1 | **数学模型** | 集合/索引、参数（单位）、变量（类型/维度）、目标（逐项解释、量纲一致）、逐条编号约束（业务解释、硬/软、违约码） | 只有一句自然语言描述 |
| 2 | **formulation 强度** | 至少两套对整数解等价的写法，各自规模、**实测** LP 松弛值、对称性处理 | 只写一套；「约束少 = 好解」 |
| 3 | **合法下界** | 组合界 / LP / Lagrangian / 列生成之一，可复算，写明相对哪个放松 | 拿启发式最好解当下界 |
| 4 | **复杂度与可解边界** | NP-hard 依据、固定参数可解情形、规模阶、精确可解上界 | 只说「规模大就难」 |
| 5 | **最优性证书** | $z_{IP}$、下界/对偶界、`MIPGap`、`NodeCount`、`Runtime`、`Status`；小规模独立精确解逐位对照 | 只给一个目标值就写「最优」 |
| 6 | **算法与理论定位** | 邻域、终止判据、gap 相对谁；**证明类型已分清**（正确性/近似比/locality gap/难度，见 `证明规程.md` §0）；近似比带紧例；文献与实测分开 | 「几个算例上最优」→「保证最优」 |
| 7 | **benchmark 与规模分档** | 标准库名称或生成器 + 全部种子 + 参数；分档用途；绝对目标值不跨文献比 | 临时随机造点就报百分比 |
| 8 | **求解性能档案**（M1=求解器直用时为硬工件） | 同机/同线程/同时限/同 gap 下的档案对照；各档目标值一致性；加速归因到层；失效项照写 | 只报「快了 N 倍」，不报线程数与解是否一致 |

细则见：`模型库.md`（工件 1、2）、`松弛与下界.md`（工件 3）、`算法手册.md`（工件 6）、`算例与基准.md`（工件 7）、`求解器调优.md`（工件 8）。

## 2. MILP 模板（可直接抄）

```python
import numpy as np
from scipy.optimize import milp, LinearConstraint, Bounds
from scipy.sparse import csr_matrix

# 1) 单一变量布局：MILP 与 LP 松弛共用同一套 (c, A, lb, ub)
#    例：z = [y_0..y_{m-1}, x_00..x_{0,n-1}, ..., x_{m-1,n-1}]
c  = np.array(...)
A  = csr_matrix(...)
lo = np.array(...); hi = np.array(...)
bnd = Bounds(np.array(lb), np.array(ub))

# 2) 整数解
ip = milp(c=c, constraints=LinearConstraint(A, lo, hi), integrality=np.ones(nv),
          bounds=bnd, options={"time_limit": TL, "mip_rel_gap": 0.0})

# 3) LP 松弛：只切 integrality，其余完全相同
lp = milp(c=c, constraints=LinearConstraint(A, lo, hi), integrality=np.zeros(nv),
          bounds=bnd, options={"time_limit": TL})

# 4) 必写断言
assert lp.fun <= ip.fun + 1e-6 * max(1, abs(ip.fun))   # 下界合法
assert ip.status == 0 and getattr(ip, "mip_gap", 0) <= 1e-9   # 才允许写「最优」
```

- Gurobi：`ObjVal` / `ObjBound` / `MIPGap` / `NodeCount` / `Runtime` / `Status`；`Model.relax()` 给 LP。
- HiGHS：`fun` / `mip_dual_bound` / `mip_gap` / `mip_status` / `mip_node_count`。
- 不想手写就用 `scripts/milp_lab.py`：JSON 描述模型，直接给 LP 界、整数解、integrality gap、诊断与解校验。

## 3. formulation 强度检查

- 逐条（$O(mn)$）与聚合（$O(m)$）对整数解等价，**对 LP 通常不等价**；实测 `integrality_gap_pct`。
- 弱形式 LP 界若等于「完全放松某约束」的组合界，说明该约束在 LP 中失效（p-median 聚合约束是标准例子）。
- Big-M 取最小合法值，说明来源，做一次 M 敏感性。
- 对称解要破缺或声明不破缺的原因。
- 报变量数、约束数、非零元；约束少不等于求解快，要同时看 gap 与 CPU。

## 4. 复杂度与理论的引用纪律

- 复杂度结论必须写清「关于哪个参数」与「最坏/期望」。
- NP-hard 要给出归约来源或引用；固定参数可解要写清固定的是谁（如 $p$ 固定）。
- 近似比/locality gap 必须带适用条件：度量？权重？容量？$p$ 是否固定？
- 未核对原文的写「定位用，未验证」，不许直接进结论。

---

## 5. 求解器诊断与降级

| 情形 | 处理 |
|---|---|
| `Status=OPTIMAL` 且 `MIPGap=0` | 可写「求得最优」，同时报下界 |
| `Status=LIMIT`（超时） | 写「时限内最好可行解 + 当前 gap」，不写最优 |
| 无 Gurobi 许可 | 降级 HiGHS（`scipy.optimize.milp`），字段名不同，报告要注明 |
| 连 HiGHS 也没有 | 固定参数枚举 / DP / 只给下界，并把「无精确解」写进局限 |
| 数值不稳定 | 缩放系数、收紧 Big-M、检查容差；不要靠调 `MIPGap` 掩盖 |

## 6. 措辞纪律

| 想写 | 必须先有 |
|---|---|
| 「最优解」 | `Status=OPTIMAL` + `MIPGap=0` + 合法下界；小规模另有独立精确解 |
| 「提升 x%」 | 分母明确（BKS / LB / 哪条基线）、同算例同口径、样本规模 |
| 「LP 松弛是紧的」 | 只写「在本次 N 组算例上 gap=0」；不宣称理论上 ideal |
| 「算法有效 / 有保证」 | 近似比或 locality gap 的**确切适用条件** |
| 「文献结论」 | 标年份与适用条件，与本文实测分栏 |
| 「平均成本 / 总距离」 | 声明量纲、坐标系、距离度量；不可跨文献比 |

## 7. 与阶段门的接口（硬判据）

| 阶段 | 必须落盘的工件 |
|---|---|
| Stage 2 · 数学模型 | 工件 1、2、4：模型卡、两套 formulation 的 LP 对比、复杂度 |
| Stage 3 · 数据与基线 | 工件 7：算例库或生成器 + 种子 + 分档；基线是否带证书 |
| Stage 4 · 精确求解与可信度 | 工件 3、5：合法下界、求解器诊断、独立精确解对照 |
| Stage 5 · 算法设计 | 工件 6：邻域、终止、gap 相对谁、理论保证的适用条件 |
| Stage 6 · 计算实验 | 复核 3、5：$LB\le z_{IP}$、不同 formulation 整数解一致、超时单列 |

**一句话红线**：Stage 2 没写出下界与复杂度、Stage 4 没写出最优性证书，这道门不许过——即使实验流程、统计、交互留痕全都完美。
