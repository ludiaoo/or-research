# 算法手册 · 选型、设计、实现与调参

> 先问三件事：**要多大的规模、需不需要最优性证书、有没有结构可用**。
> 答案决定走精确、启发式还是混合，不要一上来就 ALNS。
>
> 可运行骨架见 `scripts/algotemplates/`（`alns.py` / `sa.py` / `ts.py` / `selftest.py`），
> 接入方法见 `算法实现模板.md`，理论保证的写法见 `证明规程.md`。

## 1. 选型决策树

```
需要证明最优？
├─ 是 → 规模多大？
│      ├─ 小（MILP 变量 < 1e5）→ MILP / CP-SAT，配合上下界
│      ├─ 中 → 分支定价 / 割平面 / 专用 DP
│      └─ 大 → 分解（Lagrangian、Benders、列生成）或「精确 + 启发式热启动」
└─ 否 → 有时间上限吗？
       ├─ 有严格时限 → 构造式 + 局部搜索（保证 anytime 有解）
       └─ 可以跑几分钟 → ALNS / 混合遗传 / 数学启发
```

补充判据：

- 问题有**全幺模**结构（网络流、指派、运输）→ 直接 LP，不要上启发式。
- 目标/约束可分解成「主问题 + 独立子问题」→ 列生成或 Lagrangian。
- 规模小但非线性 → 先线性化，再判断；不要直接上 MINLP。
- 有强下界可算 → 启发式 + gap 报告，比「只报目标值」有价值得多。
- **可行性本身很难**（时间窗 + 同步 + 资源）→ 先解决可行性再谈优化，CP-SAT 或约束修复优先于目标导向搜索。

### 1.1 问题族 → 范式映射（避免默认 ALNS）

| 问题族 | 首选 | 次选 | 慎用 | 理由 |
|---|---|---|---|---|
| VRP 类（含多车多程） | 构造 + 局部搜索 → ALNS | 列生成（小规模精确）、数学启发 | 纯 GA | 邻域天然有「移除-重插」语义 |
| 排产 / 作业车间 | CP-SAT | 优先规则 + 局部搜索 | 大 M 的 MILP | 析取约束用 $M$ 极弱 |
| 选址 / 覆盖 | MILP | 贪婪 + 局部搜索 | ALNS | 解结构是集合，不是排列 |
| 装箱 / 切割下料 | 列生成、MILP | FFD + 局部搜索 | GA | 模式组合天然适合列生成 |
| 网络设计 / 设施扩容 | Benders、列生成 | Lagrangian | ALNS | 主-子问题结构清晰 |
| 指派 / 运输 / 匹配 | LP（全幺模） | — | 任何启发式 | 直接 LP 就最优，上启发式是浪费 |
| 背包类 / 小规模组合 | DP | MILP | GA | 状态可枚举，DP 精确且快 |
| 带复杂可行性（同步、时窗） | ALNS（带修复） | CP-SAT | 纯 GA + 罚函数 | 罚函数会把搜索引向不可行区 |

**选型论证要写进 `05_算法设计.md`**：为什么这个范式适配这个结构，而不是「因为常见」。

## 2. 精确方法

### 2.1 MILP（分支定界 + 割）

- 先给**紧凑且强**的 formulation（见 `模型库.md`），再谈求解器参数。
- 关键参数：`time_limit`、`mip_rel_gap`、`threads`（论文实验建议单线程）、cuts 强度、presolve。
- 必须记录：`ObjVal`、`ObjBound`、`MIPGap`、`NodeCount`、`Runtime`、`Status`。
- 小规模一定要和**独立精确解**（枚举/DP）对照，防止模型写错却「求解成功」。

### 2.2 CP-SAT

适合逻辑约束多、时间窗、排班、可行域不规则的问题。它与 MILP 的建模语言差别很大，别照搬。

| 需求 | 写法 | 注意 |
|---|---|---|
| 任务占用时间区间 | `NewIntervalVar(start, size, end)` | `size` 可为变量；三个量满足 `start + size == end` |
| 同一机器上的任务不重叠 | `AddNoOverlap([iv1, iv2, ...])` | 直接表达析取，比大 $M$ 强得多 |
| 资源容量（人力/电量） | `AddCumulative(intervals, demands, capacity)` | 累计约束，MILP 里要展开成时间索引变量 |
| 任务可选（可跳过/可由他车做） | `NewOptionalIntervalVar(start, size, end, is_performed)` | 配合 `OnlyEnforceIf` 做条件约束 |
| 条件约束 | `model.Add(expr).OnlyEnforceIf(lit)` | **替代大 $M$**，这是 CP-SAT 的核心优势 |
| 目标 | `model.Minimize(expr)` | 取 `solver.BestObjectiveBound()` 作下界 |

报告纪律：

- 界必须注明「CP-SAT bound」，**不可与 LP 界并列同一列**——两者来源不同，不可比。
- 与 MILP 对比时，同一时限比目标值可以，**比节点数没有意义**（节点定义不同）。
- CP-SAT 没有 LP 松弛，所以「LP 界」这件事在这里不存在；要 LP 界就换 MILP。

### 2.3 动态规划

DP 的价值在于**小规模精确对照**和**子问题求解**（列生成定价、Lagrangian 子问题）。写之前先答四问：

1. **状态要捕获什么才能决定未来？** 少了这个信息，未来决策就会做错。
2. **是否无后效？** 已经做过的决策对未来的影响，是否全部体现在状态里。
3. **状态数是多少？** 逐维相乘，超 $10^7$ 基本不可行。
4. **每个状态的转移是否覆盖全部决策？** 漏一种转移 = 漏一类解。

| 技巧 | 适用 | 说明 |
|---|---|---|
| 位掩码 | $n\le 20$ 的集合型（TSP、指派） | 状态 $2^n\cdot n$，$n=20$ 约 $2\times10^7$ |
| 按层滚动 | 0/1 背包、按阶段递推 | 只留上一层，空间从 $O(nW)$ 降到 $O(W)$ |
| 区间 DP | 括号匹配、矩阵链、部分路径 | 状态为区间 $[l,r]$，$O(n^2)$ 或 $O(n^3)$ |
| 状态压缩（轮廓线） | 网格铺砌、棋盘覆盖 | 逐格推进，状态是「切口」上的占用情况 |
| 记忆化搜索 | 状态稀疏、边界复杂 | 自顶向下好写；迭代版更快但要自己定序 |

- **复杂度 = 状态数 × 每状态转移数**，先估阶再写代码。写不出来往往是状态设计错了，不是代码问题。
- 常见坑：边界初始化漏一种（空集、单元素）；同一状态被重复计算（忘记忆化）；状态里放了与未来无关的量（状态爆炸）。
- 走 DP 的路子要配一个**小规模暴力枚举**对撞，否则很容易「跑得通但算错」。

### 2.4 分支定价 / 分支割

只在「LP 界明显不够 + 有良好定价子问题」时才值得做。工程量是 MILP 的数倍，先确认贡献真的需要它。

**结构**：

```
RMP（限制主问题，只含已生成的列）
  ↓ 求解得对偶 π
定价子问题：找 reduced cost < 0 的列（通常是带资源约束的最短路 ESPPRC）
  ↓ 有负列 → 加入列池，回到 RMP
  ↓ 无负列 → RMP 最优 = 该节点的 LP 界
分支（若解非整数）→ 在子节点重复上述过程
```

**四个必须想清楚的设计点**：

| 设计点 | 做法 | 失败表现 |
|---|---|---|
| 定价子问题 | 资源约束最短路（标签算法 + 支配规则 + 剪枝）；规模小可暴力 | 定价比主问题还慢，整体卡死 |
| 列池管理 | 每轮只加 reduced cost 最负的若干列（如 10–50），不是全部 | 主问题规模爆炸，每轮求解变慢 |
| 分支规则 | 弧分支或 Ryan–Foster（按客户对）；**不要分支在列上** | 分支后定价子问题结构被破坏 |
| 对偶稳定性 | 平滑：$\pi\leftarrow(1-\alpha)\pi_{old}+\alpha\pi_{new}$，$\alpha\approx0.3$ | 对偶值震荡，定价反复生成同类列 |

- **只解 LP 得到的是下界**；要整数解必须 branch-and-price，或对最终列池做一次整数规划（**不保证最优**，报告时要写清）。
- 报告字段：根节点 LP 界、节点数、生成列数、定价调用次数、每层平均定价耗时。
- 常见失败：定价子问题本身 NP-hard 又没剪枝；退化导致同一列反复生成（加列去重）；主问题数值范围过大（先缩放成本）。

## 3. 构造式启发式（基线必备）

| 方法 | 适用 | 一句话 |
|---|---|---|
| 贪婪插入 | 选址、覆盖、集合 cover | 每步选边际成本最小 |
| Clarke–Wright 节约 | CVRP | 按节约值合并路径 |
| 扫描法 sweep | 带空间聚集的路径 | 按极角分组再排 |
| 最近邻 | TSP | 快，但差 |
| 后悔值插入 | 带时间窗 | 插入代价差最大的先插 |
| 随机化贪婪（GRASP） | 通用 | 候选表随机取，再局部搜索 |

**基线的作用是给分母**。基线太弱，提升幅度就虚高；业务方或审稿人第一个问的就是这个。

### 3.1 先量差距，再决定要不要上算法

构造解写完，先做一件事：**在目标规模上量化它与精确解的差距**。差距小到不值得，就不上算法。

| 实测（一维下料） | 数值 |
|---|---|
| 本案例（80 件 / 6 规格） | FFD 17 根 = 精确解 17 根，gap 0% |
| 60 个随机小算例（种子 1） | 59/60 达最优（98%），平均 0.28%，**最多多 1 根** |
| 精确解耗时 | 0.006 s（80 件）/ 0.6 s（200 件） |

结论：这个规模上写 ALNS 只会多 200 行代码和一批新错误，省不下 1 根料。
**「不上算法」是结论，不是偷懒**，但必须由这组数字支撑，不能凭感觉说「够用了」。

判断线：

- 构造解 gap ≤ 1 个目标单位、且精确解在秒级 → **不上**，老实交构造解 + 精确解；
- 构造解 gap 明显、但精确解在时限内 → **先调 formulation**（Stage 2 的事），再说算法；
- 精确解超时限、构造解又差得远 → 才轮到元启发式，且必须有下界说明差多少。

> 反过来的错也很常见：规模早就超出求解器，还在调参数硬顶。
> 判断依据是「求解器在你的时限内能否证到 gap ≤ 目标」，不是「跑出来了就行」。

### 3.2 基线的强弱决定分母，而分母决定一切百分比

同一个「周负荷峰值可降 21%」，配不同的基线，含义完全不同：

| 基线 | 可信度 | 该怎么说 |
|---|---|---|
| 最优解（证书） | 高 | 「已达最优，无可改进」 |
| 实际历史排产（真实记录） | 高 | 「相对现有做法可降 x%」，并说明现有做法的口径 |
| 规则启发式（LPT/EDD 等） | 中 | 「相对 LPT 可降 x%」，不能说「相对现状」 |
| 随机派单 / 合成数据默认分配 | **低** | 只能写「方法能把峰值削平 x%」，并注明基线偏弱、真实幅度会收窄 |

合成算例里基线往往是随机分配，改善幅度会被系统性高估（实测某排产算例 21%，
若换成真实老师傅的排法，通常只剩个位数）。**报告改善幅度前，先回答「基线是谁做的、做得有多认真」**。

## 4. 局部搜索

| 算子 | 作用 | 单次复杂度 | 注意 |
|---|---|---|---|
| relocate（1-0） | 把一个元素移到别处 | $O(n)$ 增量 | 最常用 |
| swap（1-1） | 交换两个元素 | $O(n)$ | 易陷入局部最优 |
| 2-opt | 反转路径片段 | $O(1)$ 增量（带前缀和） | 路径类必备 |
| or-opt | 移动长度 1–3 的片段 | $O(n)$ | 比 relocate 强 |
| cross-exchange | 交换两段 | $O(n^2)$ | 跨路径 |
| ejection chain | 链式挤出 | 视深度 | 跳出局部最优 |

**增量评价是性能的关键**：每次移动只更新受影响的部分；否则 $O(n)$ 变 $O(n^2)$，规模一大就废。

**增量评价也是最容易写错的地方**——算错了不报错，只是搜索方向偏。必须做自测（见 §9）。

**邻域连通性**：确认从任意可行解能通过算子到达最优解附近；否则搜不到不是参数问题，是邻域设计问题。

## 5. 元启发式

### 5.1 ALNS / LNS（路径与调度类的推荐起点）

```
x ← 构造解; x_best ← x; T ← T0
while 未终止:
    d ← 按权重选破坏算子; r ← 按权重选修复算子
    x' ← r(d(x))
    if accept(x', x, T): x ← x'
    if f(x') < f(x_best): x_best ← x'
    更新算子权重（按历史得分）; T ← 降温
```

设计要点：

- **破坏算子**：随机移除、最差移除、相关性移除（Shaw）、路径/整段移除、历史频繁边移除。
- **修复算子**：贪婪插入、后悔值插入、带噪声贪婪。
- **接受准则**：模拟退火最稳；记录当前解与最优解两条轨迹。
- **权重更新**：每 $N$ 轮按得分（新最优 / 改进 / 接受）更新，保留探索概率 $\epsilon$。
  常用形式：$w_d\leftarrow(1-\rho)w_d+\rho\cdot\pi_d$，$\rho\approx0.1$，最低权重下限防止算子被永久淘汰。
- **规模自适应**：移除比例随规模调（如 10%–40%），固定个数在大算例上会失效。
- **破坏后必须能修回来**：修复算子要么保证可行，要么带明确惩罚；否则大量迭代浪费在不可行解上。

### 5.2 禁忌搜索

| 要素 | 做法 | 常见错误 |
|---|---|---|
| 禁忌对象 | 记**移动**（如「把 $i$ 从位置 $a$ 移到 $b$」）而非整解 | 记解 → 表太大且几乎不命中 |
| 禁忌表结构 | 环形缓冲 + 哈希索引；每条带剩余任期 | 用列表线性查找 → 每步 $O(\text{表长})$ |
| 禁忌长度 | $5\sim15$；或随规模 $0.9n+10$ 量级；**必须做敏感性** | 固定为 7 就交给论文 |
| 候选集 | 小规模用全邻域；大规模抽样（每步 100–1000 个移动） | 全邻域 + 大规模 → 一步跑几秒 |
| 特赦准则 | 若移动产生优于历史最优的解，**无视禁忌接受** | 没有特赦 → 明明有更好解却错过 |
| 多样化 | 频率记忆惩罚 + 长期停滞时重启（从最优解扰动或随机） | 只有短期记忆 → 在局部区域反复绕 |
| 终止 | 最大迭代 / 无改进迭代数 | 达到下界时也应停 |

禁忌搜索的优势是**不依赖随机性**，结果稳定、易复现；劣势是邻域大小直接决定每步成本。适合中大规模、邻域可高效评价的问题。

### 5.3 模拟退火

**这是最容易被写成「随便调个温度」的算法**。四个量必须标定，不能拍脑袋：

| 量 | 标定方法 | 常用取值 |
|---|---|---|
| 初温 $T_0$ | 采样若干初始邻域解，取平均劣化 $\bar{\Delta}$，令 $e^{-\bar\Delta/T_0}=0.8$，即 $T_0\approx4.48\bar\Delta$ | 使初始接受率约 80% |
| 降温系数 $\alpha$ | 由「总迭代数 $N$ + 末温」反推：$\alpha=(T_{end}/T_0)^{1/N}$ | 几何降温 $0.95\sim0.999$ |
| 链长 $L$ | 每个温度下的尝试次数；与邻域规模同阶 | $L\approx 100n$ 或邻域大小 |
| 末温 $T_{end}$ | 使最差移动的接受概率 < 1% | $T_{end}\approx 0.01\bar\Delta$ |

- **接受准则**：$\Delta\le0$ 必接受；$\Delta>0$ 以 $e^{-\Delta/T}$ 接受。
- **重热**：连续 $K$ 个链无改进，令 $T\leftarrow\max(T\cdot2,\ T_0/10)$；用于跳出深谷，但会拉长 anytime 曲线。
- **必须记录**：当前解轨迹与最优解轨迹两条线。只画最优轨迹会掩盖实际波动。
- **常见错误**：温度按迭代数固定降（与实际尝试次数脱钩）；链长设为 1（退化成随机游走 + 记录最优）；初温过高导致前半程纯随机。

### 5.4 遗传 / 模因算法

| 要素 | 做法 | 说明 |
|---|---|---|
| 编码 | 排列（路径）、0-1（选择）、整数（分配）、**随机键**（连续优化映射到排列） | 编码决定交叉算子能不能用 |
| 初始化 | 随机 + 构造式解混合（如 20% 用贪婪插入） | 全随机起步等于浪费前几十代 |
| 选择 | 锦标赛 $k=2\sim3$（推荐）；排名选择；轮盘赌**易早熟** | 适应度差距大时轮盘赌会垄断 |
| 交叉 | 排列：OX / PMX / ERX；0-1：均匀交叉；随机键：SBX / 算术 | 交叉后必须修复可行性 |
| 变异 | 排列：交换、逆序（2-opt 型）、插入；0-1：位翻转 | 变异率按 $1/n$ 量级设定，不是固定 0.1 |
| 修复 | 容量/时间窗违反 → 修复算子或罚函数 | 只在交叉后修，不要每代全局修 |
| 替换 | 精英保留（前 $k$ 名直接进下一代）+ 代际替换 | 无精英 → 最优解会丢 |
| 早熟判定 | 种群多样性（平均汉明距离 / 目标方差）连续 $G$ 代低于阈值 | 触发：注入随机个体、提高变异率、重启 |

- 参数：种群 50–200，交叉率 0.8–0.95，变异率 $1/n$ 量级。
- **GA 不适合**解结构是集合、且邻域语义天然的问题（如 VRP）；强行用会因为「交叉破坏好结构」而表现平庸。选它之前先回答：为什么不用 ALNS。
- 报告必须给**收敛曲线**与**多次独立运行分布**，不是一次最好结果。

### 5.5 数学启发（matheuristic）

- 大邻域 + 子问题用 MILP 精确解（如固定大部分变量，只优化一小块）。
- 效果好但每次子问题求解时间要控住，否则 anytime 行为很差。
- 关键参数是**子问题规模**：太大则单步慢，太小则改进有限。做规模-收益曲线。

---

## 6. 调参与预算

- **调参集与测试集必须分开**。在测试算例上调参 = 数据泄漏。
- 优先用**少参数**的算法；参数越多，调参预算越大，结论越脆。
- 常用做法：网格 / 随机搜索（预算固定，如 100 次运行），或 irace/SMAC（若环境允许）。
- 报告：调参集、搜索空间、预算、选中的参数、是否有敏感性分析。
- 参数敏感性至少做「关键 2–3 个」，画趋势图，不要只报最好那组。

---

## 7. 终止与 anytime

| 判据 | 适用 | 注意 |
|---|---|---|
| 时间上限 | 对比实验 | 必须同硬件同线程 |
| 迭代/无改进轮数 | 算法内部 | 要说明与规模的关系 |
| 达到下界 | 有合法 LB | 最强，但通常达不到 |
| 目标 gap | 有 LB | 报告「达到 x% gap 的时间」 |

**anytime**：随时能给可行解是启发式的核心优势。报告 primal integral（面积）比只报终点值更能反映过程。

---

## 8. 常见失败模式

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 结果比下界还低 | 解不可行 / 目标算错 / 下界口径不同 | 用独立校验器重算目标与约束 |
| 大规模效果骤降 | 参数未随规模缩放、邻域固定大小 | 做规模敏感性，调移除比例 |
| 换个种子结果差很多 | 随机性未控制、重启不足 | 报多次运行分布，不报单次最好 |
| 跑得比基线慢一个量级 | 增量评价缺失、重复全量重算 | profile 热点 |
| 消融后没差别 | 算子冗余 / 调参不公平 | 统一调参预算再比 |
| 小算例不如精确解 | 邻域不连通 / 终止太早 | 先在小算例上验证能达到最优 |
| 增量评价与全量重算不一致 | 增量公式写错 | 跑 `selftest.py` 对撞 |
| GA 第 20 代就不再改进 | 早熟 / 无精英保留 / 变异率过低 | 看多样性曲线 |

## 9. 实现与自测（硬要求）

### 9.1 三个必须存在的测试

| 测试 | 做法 | 不做的后果 |
|---|---|---|
| **增量 vs 全量** | 随机解 + 随机移动，比较增量更新的目标与从头重算 | 搜索方向系统性偏移，且不报错 |
| **可行性一致** | 增量维护的可行性标记 vs 独立校验器 | 返回「可行」的不可行解 |
| **小算例对撞** | $n\le10$ 与精确解/暴力枚举比较 | 算法能跑但永远够不到最优 |

`scripts/algotemplates/selftest.py` 提供前两项的通用实现（传入你的 problem 适配器即可）。

### 9.2 性能自检

- **profile 热点**：先确认时间花在评价还是移动上；80% 时间在评价就别优化数据结构。
- **单步成本随规模的变化**：$n$ 翻倍，单步时间应该大致线性或 $n\log n$；变成平方说明增量失效。
- **anytime 曲线**：记录每 $k$ 次迭代的最优值，画出来；曲线早早走平说明搜索已死。

### 9.3 可运行骨架

`scripts/algotemplates/` 下四个引擎与问题解耦，通过 `Problem` 接口接入（见 `算法实现模板.md`）：

| 文件 | 内容 |
|---|---|
| `alns.py` | 算子注册、自适应权重、SA 接受、anytime 记录 |
| `sa.py` | 初温自动标定、几何降温、重热 |
| `ts.py` | 禁忌表（环形缓冲）、候选集、特赦、多样化 |
| `selftest.py` | 增量评价 vs 全量、可行性一致性对撞 |

**骨架不是拿来直接交差的**：它保证的是工程正确性（增量对不对、种子可复现），算法设计仍需按 §1–§5 自己想清楚。
