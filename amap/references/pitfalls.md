# 坑清单（按症状查）

每条都是实际踩过的。症状 → 原因 → 处理。

---

## 一、底图出不来 / 出的是别人的地图

### 症状：底图一片灰白，或有「地图加载失败」字样
- **可能**：key 不是 Web 服务类型，或没开通「静态地图」服务。
- **查**：浏览器直接打开
  `https://restapi.amap.com/v3/staticmap?location=116.39,39.90&zoom=12&size=512*512&key=KEY`
  - 回 PNG → 通
  - 回 JSON（`{"status":"0","info":"INVALID_USER_KEY"}`）→ key 错
  - 回 `USERKEY_PLAT_NOMATCH` → key 平台类型不对，去控制台换「Web服务」
  - 回 `INVALID_USER_SCODE` → 这是 JS API 的安全密钥缺失，不是 Web 服务的错

### 症状：在 WorkBuddy / 内网预览里底图是白的，浏览器单开又是好的
- **原因**：预览服务可能有自己的资源代理；腾讯位置服务那种代理**只转发底图瓦片**，不转发任何 WebService 路径（`/ws/distance`、`/ws/geocoder` 全 404）。
- **处理**：不要指望宿主代理，直接用高德静态地图出图 + base64 内嵌，彻底绕开运行时网络。

### 症状：想用高德 JS 地图，但 `new AMap.Map()` 报 `USERKEY_PLAT_NOMATCH`
- **原因**：Web 服务 key 拿去当 JS API key 用了。
- **处理**：控制台新建一个只勾「Web端(JS API)」的 key，配 `securityJsCode` 或代理，并**设域名白名单**。别把业务 key 放前端。

## 二、线画出来了，但位置不对

### 症状：整条线路相对道路平移几十到几百米，形状没问题
- **原因**：Python 与 JS 的墨卡托公式不完全一致（一个用 `ln(tan(π/4+φ/2))`、一个用 `ln((1+sin)/(1-sin))/2`，浮点误差极小但常数或系数抄错就会整体偏）。
- **处理**：两边都写成 `(0.5 - ln((1+s)/(1-s))/(4π)) * N`，`N = 256·2^z`。改完用「仓库位置应落在画布中心偏移后的位置」核对一次。

### 症状：线飘到海里 / 偏到隔壁城市
- **原因**：坐标系混用（数据是 WGS-84，底图是 GCJ-02，差了 100–700 m；或者反过来）。
- **处理**：GCJ-02 全链路不转换。若数据源是 GPS 原始（WGS-84），只在**入库时**转一次，之后所有环节都当 GCJ-02 对待。

### 症状：线穿过江面、穿过小区、穿过铁轨
- **原因**：用门店顺序连了直线，或者某段没取到 `direction` 就退化成直线。
- **处理**：每段都要真实 `polyline`；取不到就让它报错，别静默退化成直线——那种图看着像真的，最危险。

## 三、数字对不上

### 症状：地图上车队里程之和 ≠ 报表总里程，差 3–5%
- **原因**：`/v3/distance`（矩阵）与 `/v3/direction`（路径几何）对同一对点给的里程本来就不同（实测差 4.2%）。
- **处理**：**报表一律用矩阵口径**，`direction` 只用来画图，并做交叉校验（差 >3% 打警告）。不要拿路径几何累加去当里程。

### 症状：优化收益大得离谱
- **原因**：把 `type=0`（直线距离）当路网距离用了。同一对点实测 `type=0` 给 808 m，`type=1` 给 1527 m。
- **处理**：`type=1`。并且跑一次「路网/直线中位比值」，落在 1.15–1.75 才正常。

### 症状：矩阵「完美」——不对称 0 对、三角违反 0 处、但距离全 0
- **原因**：读缓存时只填了缓存字典，**没回填进矩阵**，然后因为"缓存全命中"没发新请求。
- **处理**：命中后必须回填；结尾加硬断言「任何 D[i][j] ≤ 0 就退出」。

### 症状：第二次跑全命中假数据
- **原因**：缓存 key 里没有 provider（先跑了 mock/euclid，再跑 amap 命中的还是假的）。
- **处理**：缓存文件按 provider 分文件名，或 key 里带 provider。

### 症状：全新跑一次却显示「命中 6480 次」
- **原因**：先请求、再查缓存时把本次写入的也算成命中。
- **处理**：把 `get()`（查+可能写）和 `peek()`（只读）拆开。

## 四、图不好看 / 被切

### 症状：线路在画布边缘突然断掉
- **原因**：视野只按门店/仓库坐标算，绕行路段比门店更靠外。
- **处理**：把所有 `routes[].path` 的点也纳入包围盒（`build_map.py` 的 `collect_points` 已经这么做）。

### 症状：内容只占画布中间一小块，四周大片留白
- **原因**：`--pad` 太保守，或 zoom 自动降了一级。
- **处理**：`--pad 0.86～0.90`；内容形状是竖长条时用方画布（1024×1024）比横画布合适。

### 症状：宽屏下左右两条大灰边
- **原因**：画布是 1:1，屏幕是 16:9，等比 contain 必然留边。
- **处理**：接受它（保证不变形、坐标不错位），或把背景做成浅灰卡片样式。**不要**用 `object-fit: cover` 裁切——除非 SVG 也用 `preserveAspectRatio="slice"` 同步裁，否则线立刻错位。

### 症状：左侧浮层挡住了线路主体 / 挡住了地图版权
- **处理**：`--shift-px -80` 把视野中心西移（内容右移）；版权文字自己在右下角补一个 `© 高德地图`（高德底图自带的版权在左下角，常被挡住）。

### 症状：灰色虚线残影看不见
- **原因**：2px 灰虚线压在高德彩色道路底图上，和背景路网糊在一起。
- **处理**：残影画两层——先白色 5.2px 打底（opacity .55），再 2.4px `#5b6270` 虚线（opacity .85）。

### 症状：线宽随窗口缩放变得忽粗忽细
- **处理**：SVG 描边加 `vector-effect="non-scaling-stroke"`，dash 也会随之按屏幕像素算。

### 症状：首屏画布尺寸算错（图片还没加载就量了高度）
- **处理**：在 `img.onload` 里再算一次 `fitCanvas()`，不要只在 `DOMContentLoaded` 算。

## 五、交互

### 症状：勾选后旧线路还在，越点越多（高德 JS 层）
- **原因**：AMap 2.0 里 `overlay.setMap(null)` 和 `map.remove([数组])` 都不可靠——不报错，但线留在图上。
- **处理**：每次重绘直接 `map.clearMap()` 全清再重建（61 个点 + 6 条线，几十毫秒）。别图省事只删路线层。

### 症状：接入高德 JS SDK 后，页面按钮变成灰底浅字（像被禁用）
- **原因**：SDK 注入了全局 `button` 样式，把自己的按钮覆盖了。
- **处理**：给面板内的按钮提高选择器特异性并加 `!important`（`.panel .tabs button { background: #fafafa !important; ... }`），同时 `appearance: none`。

### 症状：JS key 配了但地图还是静态图
- **排查**：① 打开控制台看 `AMap` 是否 undefined（SDK 没加载）；② 看是否 `USERKEY_PLAT_NOMATCH`（key 不是 JS 类型）；③ 看 `securityJsCode` 是否漏配（2021.12 之后申请的 JS key 必须配）；④ 域名白名单是否包含当前访问地址（`file://` 打开时 referer 为空，多数白名单会拒绝——用 `http://localhost` 测）。
- **处理**：代码里要给 SDK 加载失败留兜底，别让整页白屏。

### 症状：填好了 `.env` 却仍报「缺 key」
- **排查**：① 文件名是 `.env` 不是 `.env.txt`（Windows 记事本容易加后缀，`dir /a` 看全名）；② 写在 `KEY=VALUE` 一行里，等号两边不要空格、不要中文引号；③ 变量名拼写（`AMAP_KEY`/`AMAP_JS_KEY`/`AMAP_JS_SECRET`）；④ 当前进程里是否有旧的空环境变量把 `.env` 顶掉了——**环境变量优先级最高**，`set AMAP_KEY=` 清掉再试。
- **处理**：`python -c "import amap; print(amap.load_env(reload=True).keys())"` 只打印键名，能立刻确认读到了哪几项；路径不对时用 `AMAP_ENV_FILE=/abs/path/.env` 显式指定。
- **另一个坑**：`.env` 被提交进仓库。它必须出现在 `.gitignore` 里；如果已经提交过，光加忽略没用，历史里仍在——需要 `git rm --cached .env` 并**轮换 key**。

### 症状：勾选「全选」后合计里程比面板总里程多 0.1
- **原因**：逐条里程已四舍五入，再求和。
- **处理**：全选时直接显示 `sc.total_km`，只有部分选择才用子集求和。

### 症状：切换方案后勾选状态莫名其妙
- **处理**：换方案时把 `hidden` 重置为全选——不同方案的线路下标含义不同。同一方案内保留勾选。

### 症状：点按钮没反应
- **排查顺序**：① 面板数字变了吗（变了说明 JS 活着，只是地图没画）；② 控制台有红字吗；③ 页面里 `#tabs` 有没有 button（没有说明初始化在更早的地方挂了）。
- **通用做法**：面板渲染放在地图绘制**之前**，地图失败也要能切 tab；所有绘制包 `try/catch` 并把错误显示在面板上，**不许静默失败**。

## 六、数据本身的反直觉现象（不是 bug）

### 真实路网距离不满足三角不等式
实测 9076 处违反（4.20%），因为 `/v3/distance` 用「速度优先」：一条更长但不堵的路，里程反而大。
**不要做 Floyd 闭包**——闭包会把未经导航验证的「绕行捷径」写进矩阵；保留原值只影响下界（MST 只需非负性），偏保守。

### 里程更短 ≠ 更便宜
实测两方案：140.9 km / 686.3 元 vs 146.9 km / 470.2 元。外协车 6 元/km + 180 元起步，里程短反而贵。
**目标函数写「最小里程」会选错方案。**

### 固定成本在局部搜索里看不见
外协 180 元起步价，单店 relocate 永远看不出关掉一条线的价值，必须加「整线关闭」算子。

## 七、无人机-卡车（drone-truck）专有

### 症状：架次的起飞点/归队点飘到几百米甚至几公里外
- **原因**：解的 `s.launch` / `s.recover` 是 **`nodes` 数组里的位置下标**，不是节点编号。直接拿去索引站点列表就会偏。
- **处理**：`nodes[s.launch]` / `nodes[s.recover]`；画之前再用「端点离最近停靠点 < 80 m」当守门（`adapt_tddo.py` 已内置，超了就打印警告）。
- **典型观感**：虚线从半空中开始，看起来像"无人机飞到一半没回来"。

### 症状：无人机航段绕着高架/河道走，形成莫名其妙的弧线
- **原因**：把架次路径也丢给了 `/v3/direction/driving`。飞机不走路网，套驾车规划等于让它开出租。
- **处理**：架次 `path` 只放「起飞站 → 各客户 → 归队站」的坐标，页面按直线画；图例里写明"航段为直线示意，不含绕行/风场/爬升"。里程要算真实航程就按欧氏距离，不要用路网距离。

### 症状：归队点和起飞点画在一起，图上看不出"卡车一直在开"
- **原因**：用同一个停靠点当起降点，或把 recover 也取成了 launch。
- **处理**：起飞用**空心圆环**、归队用**实心方块**；两者不同色块形状，读者一眼能分辨。这是 TDDO/mFSTSP 最容易被误解的一点，图例必须解释。

### 症状：同一条卡车的实线与虚线颜色不一致
- **原因**：架次按架次序号取调色板，而不是按卡车序号。
- **处理**：颜色只由卡车（线路）下标决定，架次继承所属卡车颜色；同一辆车多条架次靠**虚线间隔样式**区分（`7 5` / `3 5` / `12 5 3 5`），不要换色。

### 症状：勾掉卡车后它的架次还留在图上
- **原因**：只维护了线路级 `hidden`，没维护架次级 `hiddenS`。
- **处理**：两级状态 `hidden[线路]` 与 `hiddenS["线路:架次"]`；勾卡车时连带设置/清除它的全部架次；「反选」时架次各自翻转，不跟着卡车走。

### 症状：视野把无人机航段切掉，或禁飞区只画了半个圆
- **原因**：只按门店/卡车路径算 bbox。
- **处理**：`stops`、`sorties[].path`、`nfz`（圆心 ± 半径）都要纳入 `collect_points`。
